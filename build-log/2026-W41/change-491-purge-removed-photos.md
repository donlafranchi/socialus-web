### change #491 — removed photos are actually deleted (accepted risk due 2026-10-16; docs/purge-proposal.md option 1)

Removal stays reversible; **purge** is a second, confirmed act on a photo that is already removed, at `/admin/reports/purge` (operator only, 404 for anyone else). The operator's own session deletes the storage object (new `media operator delete` policy, `is_operator()` reading a new `operators` table, which the first purge fills from `OPERATOR_MEMBER_ID`); no service-role key. The action verifies the object is gone (HEAD on its public URL) before `report.purge` records it in `photo_purges` and clears `groups.photo_url` / stamps `photo_purged_at`. Order: bytes first, record second, so a failure between the two is a re-runnable purge, never a recorded deletion that did not happen. **Scope:** Page photos. Post photos (#460) are the same bucket and the same policy; wiring them in follows that PR. Migration `20261007250000_photo_purge.sql` (230000/240000 were taken by other branches).
