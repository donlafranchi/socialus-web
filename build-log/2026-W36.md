### T112 — Bottom nav visual refresh (thesis §2 compliance)

Scenario F046 (nav visual treatment criterion). Visual refresh of `BottomNav`, no schema change.

- Bar height 64px → **44px** (exclusive of `env(safe-area-inset-bottom)`, which stays).
- Active state pistachio/Tide accent → **charcoal `#3C3C3C`**; inactive → `#717171`.
- Icons 20px at a uniform **1.5 stroke**; active icon fills (`fill="currentColor"`), inactive outlined.
- Labels **9px/500**, 3px below the icon.
- Top border → 1px `#EBEBEB`. Background stays opaque white, no blur.
- Three tabs (Home · Explore · You) already correct from T013 — no fourth tab to remove.
- Scroll-to-top on active-tab re-tap and the `md:hidden` desktop breakpoint both preserved.

New tokens in `globals.css`: `--color-charcoal`, `--color-nav-inactive`, `--color-nav-border` (in `@theme inline`) and `--nav-height` (in plain `:root`).

**Caught by M2 code review:** the sticky mobile CTA strips on the vendor and business pages were pinned with a hardcoded `calc(64px + env(safe-area-inset-bottom))` to clear the old nav. Both now derive from `var(--nav-height)`, so the offset tracks the bar height instead of drifting.

**Caught by live verification:** `--nav-height` does not survive inside `@theme inline` — Tailwind v4 only emits namespaced theme keys (`--color-*`, `--spacing-*`, …), so the variable was dropped and the `calc()` collapsed to `bottom: auto`. Moved to the plain `:root` block. Same class of Tailwind-v4 gotcha as T111.

**M3 accessibility:** passes WCAG 2.1 AA. Active label 11.03:1, inactive 4.88:1, touch targets 44×125px, focus ring verified under real keyboard Tab. Two fixes applied during the audit — tab links now stretch to the full 44px bar height (were 36.5px), and both navs carry `aria-label="Primary"`.

Tests: `src/components/BottomNav.test.tsx` — 13 assertions covering height, colors, icon geometry, fill state, label type, landmark, touch target, and the preserved scroll-to-top behavior.
