### T113 — Scroll-to-hide bottom nav

Scenario F046 (scroll behavior criteria). Interaction-layer only, no schema change.

- New `useScrollDirection` hook — passive scroll listener, rAF-throttled, 20px sustained-travel threshold. A direction flip zeroes the accumulator, so jitter cannot cross the threshold and the bar does not flicker.
- `BottomNav` slides out on `translate-y-full` / back on `translate-y-0`, 200ms ease-out, `motion-reduce:transition-none` for reduced motion. Class toggle, not inline style, so the media query owns the animation.
- `NavVisibilityProvider` publishes `navVisible` through context — the F045 pill row reads it in T114. Provider takes `children` as a prop, so a visibility flip re-renders only consumers, not the app subtree.
- Auto-hide pauses while any `[aria-modal="true"]` (or opt-in `[data-nav-pause]`) element is mounted, watched by a MutationObserver — no per-modal wiring needed.
- Nav hides while the virtual keyboard is up, inferred from `visualViewport` vs `innerHeight`. iOS opens that gap; Android shrinks the layout viewport instead and needs no help.
- Route change restores the nav via a render-time state adjustment keyed on the pathname, so a tab switch never paints a hidden bar.

**Kind-filter pills stay put** (PM ratified 2026-09-02) — the nav slides out beneath them and they become the bottom edge. Confirmed live on `/explore`: the List/Map + market/category/day cluster held position through a full hide/show cycle.

**Caught by M2 code review:** `will-change-transform` added so the bar composites on its own layer instead of repainting the fixed footer each frame; keyboard-detection asymmetry between iOS and Android documented at the hook rather than left as a silent assumption.

**M3 accessibility:** passes WCAG 2.1 AA, no new findings. The bar keeps its `aria-label="Primary"` landmark and stays in the a11y tree while off-screen — hiding it from assistive tech would remove access, not protect it. `focus-within:translate-y-0` pulls the bar back the moment a tab link takes focus, so the 2px focus ring is never stranded off-viewport. Verified live: focus returns the bar to `translate: 0px` at `top: 767`. Contrast, touch targets (44x125), and focus order unchanged from T112.

**Live verification:** at mobile 375x812 the bar settles at `translate: 0px 100%`, `top: 812` — fully off-screen, no content jump (still `position: fixed`). A 116px scroll-up brings it back. Tailwind v4 emits `focus-within:` and `md:` variants after the base utility, so both correctly override `translate-y-full`.

### T117 — Rewire Explore from the dead vendor tables to `discoverable_items`

Substrate. Resolves the known gap left by T114 — the pills now filter real Items.

- Explore was reading `businesses`, `vendor_categories` and `market_vendors`. None of the three exist any more; PostgREST answers `PGRST205` for each, so the tab had been rendering an empty vendor list against a 404. It now reads `public.discoverable_items`, the browse index whose own `WHERE` clause is the public-visibility gate (published, not soft-deleted, no Group or a listed-and-undissolved Group) and which is already denormalized across items + members + locations + groups — one round trip per browse.
- Kind filters **server-side** on the indexed `item_kind`; the All pill sends no predicate. Search and category stay client-side over the fetched page: kind is coarse and indexed, the other two refine an already-narrow set, and T115 will pick its own fetch strategy when it moves them into the sheet.
- A pill tap refetches, but the previous page stays on screen until the next resolves — a `requestRef` counter drops stale responses. Flushing the list to "Loading…" on every tap would read as a page load, which is the opposite of T114's "instantly."
- `src/lib/explore/items.ts` — `ExploreItem` extends `FeedItem`, so `ItemFeedCard` consumes it unchanged. Explore and the Home locality feed now render the same card.
- `src/lib/explore/ewkb.ts` — PostgREST serializes `geography(Point,4326)` as hex EWKB and neither the MV nor `locations` exposes a readable lat/lng (`032_venue_distance.sql` documents that gap). Decoding client-side keeps map pins working without a fourth drop-and-rebuild of the MV and its six indexes.
- Market and day filters removed — both read `markets` / `market_vendors` through `MarketContext` and are structurally incapable of matching a row. `MarketContext` itself is untouched; Home and `/you` still consume it. Category options are now derived from the result set, because no Item uses the vendor `CATEGORIES` slugs.
- The no-filters `RecruitmentGrid` default is gone. It existed because Explore had nothing real to show.

**Caught by M2 code review:** three fixes before commit. `hexToBytes` now validates the whole string against `/^[0-9a-fA-F]+$/` — a per-byte `parseInt` reads `'0z'` as 0 rather than NaN, which would turn malformed hex into a plausible coordinate. The MV read is `.catch()`-guarded: a rejected fetch (as opposed to a PostgREST error row) previously left `loaded` false and stranded the tab on "Loading…" forever — regression test added and confirmed red without the fix. The map pin colour moved from a hardcoded `#0fab8e` to `var(--color-accent)` per the DLS rule.

**Live verification** at 375x812 against the seeded database. Every pill matches the MV's own kind distribution: All 16, Events 3, Products 4, Services 4, Ideas 2, Offers 1, Asks 1. `?kind=` round-trips both directions, and composes with view (`?kind=gathering&view=map` → 3 pins) and search (`?q=sourdough` → 1 item). Map view drops 16 pins across all seven kinds — the EWKB decode confirmed against real PostgREST output — with the pin resolving the token to `rgb(15, 171, 142)`.

**Known gap:** 9 of 16 Item detail links 404 — Group-filed Items (the `/m/` path is the individual-seller path) and the four kinds with no detail page (`ask`, `offer`, `wonder`, `initiative`). Pre-existing `itemHref` behaviour shared with the Home feed since T088; T117 changes no linking, it only makes the gap visible on a second surface. Type B stub at `planning/backlog/decision-item-canonical-urls.md`, which also carries the wider vendor/market retirement — Home is still querying `events` / `businesses` / `markets`.

Edits are held as a draft so results don't churn under the sheet — only "Show results" and "Clear all" commit, and a dismissal re-seeds from the committed value.
- Every control is a native radio/checkbox behind `sr-only`, so arrow-key navigation, group semantics and checked state come from the platform rather than a hand-rolled `role="radiogroup"`.
- `ActiveFilterChips` renders one removable chip per active secondary filter and returns `null` at zero — no empty row. Wraps rather than scrolls: a chip pushed off the right edge is a filter the member can no longer see or remove. Kind is never a chip; the pills carry it.
- `src/lib/explore/filters.ts` owns the model — parse/whitelist from the URL, chip descriptors, `removeFilter` by chip id, ISO week/weekend ranges, haversine, apply + sort. ISO weeks (Mon–Sun) rather than US Sun–Sat so "this weekend" always falls inside "this week"; under Sun–Sat a weekend result could fail the week filter.
- **Distance measures from the locality centroid** (`places.centroid`, seeded in 026), not from the device — no permission prompt, and "within 5 mi" means "of where you're browsing," which is what the location pill just said. `src/lib/explore/origin.ts` reuses `resolveFeedPlace` for the name and reads the centroid by id. No origin ⇒ radius options and "Nearest" disable with an explanatory line rather than silently emptying the surface.
- **"Recurring" reads `item_gatherings` directly.** `recurrence_rule` is not in the MV, and projecting it means a fifth drop-and-rebuild of the view and its six indexes for one radio option. `select_via_parent` resolves to the same published/listed gate the MV encodes, so the id-only read sees exactly the rows a browse may see.
- `useScrollRestoration` — the App Router's own restoration can't serve the AC, because the results arrive async and at restore time the page is one viewport tall. Recording is gated on the same `ready` flag as restoring, or the browser's reset-to-0 would overwrite the position we're about to restore.
